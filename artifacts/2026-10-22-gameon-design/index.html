GameOn Blueprint

One home for the games the kids dream up, a workflow that turns a kid's idea into a playable game in about an hour, and a path onto the iPhone.

22 October 2026Task: Draft the GameOn design (gameon#1)Reply by question number, at the end
The bet

AI can make a fun game in an hour. Not in real time, but in an hour.

So the product is the hour: a reliable path from a kid saying "I want a game where…" to that kid playing it, plus one place where every game lives and stays playable. Roblox gives kids a toolbox. GameOn gives them a game studio that takes dictation.

Decision 2

The game contract

What makes something a GameOn game. Short enough for an agent to check in a minute, and it's what lets the arcade and the phone app treat every game the same way.

  • A folder, games/<name>/, whose index.html runs with no server and no internet.
  • Works with touch and with a keyboard, and says whether it wants to be played sideways.
  • Every saved value is named gameon.<name>.….
  • A cover picture and a card file, game.json, that the arcade reads.
  • A README that keeps the kid's original idea, word for word.
{
  "name": "trampoline-battle",
  "title": "Trampoline Battle",
  "tagline": "Drop fighters onto a trampoline and bounce the other team off.",
  "credit": "Designed with my kids",
  "idea": "the kid's pitch, word for word",
  "made": "2026-10-21",
  "built_with": "Claude Opus 5.5",
  "minutes_to_first_play": 15,
  "players": "1-2",
  "sideways": true,
  "needs_internet": false
}
Decision 3

The hour

How a new game gets made, written as the steps the skills will follow. The times are targets, not measurements yet.

  1. 0:00
    PitchThe kid says what they want. It goes into a "Game idea" issue word for word, before any grown-up edits.
  2. 0:05
    First playableAn agent builds version zero from the kit's starter: title screen, controls for touch and keyboard, saving already wired up.
  3. 0:20
    Play and fixThe kid plays and says what's wrong or what's next. A grown-up steers. Each round is one commit, so a bad idea is easy to undo.
  4. 0:50
    ShipCard file, cover, README, a PR into dev. It shows up at /gameon/dev/ that night; a grown-up releases it to the main arcade.

The skills, written once and used by both tools (Claude Code loads them as skills, and Codex is pointed at the same files from AGENTS.md):

SkillWhat it does
new-gameTurns a pitch into a game folder and a first playable version from the starter.
import-gameBrings a game made as a Claude chat artifact into games/ and makes it meet the contract. Three of the six were made this way.
playtestOpens the game in a browser at phone and laptop sizes, checks for errors, takes the screenshots for the PR.
ship-gameWrites the card file and cover, checks the contract, opens the PR into dev.
Decision 4

Getting onto the iPhone

Home-screen app first Recommended

Make the arcade installable from Safari's Share menu, with an icon, full screen, and the games saved for offline play.

  • No App Store, no developer account
  • Every release reaches the phone on its own
A few hours

A real app

A small iPhone app that bundles the games/ folders and shows the arcade. Shared with friends' families through TestFlight.

  • Feels like a real app; works on a plane
  • Needs the $99/year Apple developer account
  • App Store review is a separate question for later
A day or two once games live in one repo

Native ports

Rebuild a game in Swift, the way Angry Dudes has started to.

  • Best feel
  • Days per game, so it can't keep up with an hour per game
  • Only for a breakout favorite
Days per game
Later, maybe

Order a game tonight, play it at breakfast

The natural end of "an hour, but not real time": a kid dictates an idea into the app at bedtime, it becomes a game-idea issue, an agent builds it overnight, and in the morning a grown-up checks it at /dev/ and releases it. Not for now, but the steps above are built so this needs no new machinery, only a way to start the agent.
